Clique ∈ NP — Polynomial-time Verification

Certificate: A proposed set S of k vertices claimed to form a clique.

Verifier steps:

1. Check |S| = k   → O(k) time
2. For every pair (u,v) ∈ S × S where u ≠ v, check edge (u,v) ∈ E  → O(k²) time

There are C(k,2) = k(k−1)/2 pairs. With an adjacency matrix, each lookup is O(1). Total verification: O(k²) — clearly polynomial in the input size.

Conclusion: A valid certificate is verifiable in polynomial time → Clique ∈ NP ✓

②

NP-Hardness: Independent Set ≤ₚ Clique

We reduce from Independent Set, which is known NP-complete.

Reduction Construction: Given an Independent Set instance (G, k), construct the complement graph G' = (V, E') where:

E' = { (u,v) : u ≠ v and (u,v) ∉ E }
— edges of G' are exactly the non-edges of G (same vertex set V).

Forward Direction (IS → Clique):
Suppose S is an independent set of size k in G. By definition, no edge exists between any two vertices of S in G. Therefore, for every pair (u,v) ∈ S, the edge (u,v) exists in E' (since it was absent in E). Thus S forms a clique of size k in G'. ✓

Backward Direction (Clique → IS):
Suppose S is a clique of size k in G'. Every pair (u,v) ∈ S has an edge in E'. By the complement definition, (u,v) ∉ E. So no pair in S shares an edge in G — S is an independent set of size k in G. ✓

Polynomiality of Construction: Building G' requires iterating over all O(V²) vertex pairs and flipping edge presence. This is clearly polynomial time. ✓

Conclusion: Independent Set ≤ₚ Clique. Since Independent Set is NP-complete and Clique ∈ NP, we conclude Clique is NP-complete. ∎

What is the Clique Problem? ▸

A clique in an undirected graph G = (V, E) is a subset S ⊆ V where every two distinct vertices are connected by an edge. The subgraph induced by S is a complete graph Kₖ.

Formal Decision Problem

Given G = (V, E) and integer k: does G contain a clique of size k?

Clique appears across many real-world domains. In social networks, a clique is a group where everyone knows each other. In bioinformatics, cliques in protein interaction networks identify functional complexes. In coding theory, maximum cliques relate to error-correcting codes.

The problem is closely related to Independent Set — an IS in G is exactly a clique in the complement graph G'. This symmetry is the key to our NP-completeness proof.

Algorithm Paradigm — Backtracking (Divide and Conquer variant) ▸

Design Paradigm: Backtracking — a Divide and Conquer variant

The problem is divided into subproblems: at each step, we decide whether to include or exclude a candidate vertex. Each branch recurses on a strictly smaller subproblem. Unlike pure divide-and-conquer (which always splits), backtracking abandons branches that cannot yield a solution — this is the pruning condition.

Backtracking systematically explores all possible solutions by building partial candidates incrementally, abandoning branches the moment they cannot possibly reach a solution.

The Pruning Condition

if |current_clique| + |candidates| < k → backtrack immediately.
Even if every remaining candidate joins the clique, we cannot reach size k.

The candidate shrinking is equally important: after adding vertex v to the clique, the next candidate set is restricted to N(v) ∩ remaining_candidates. Only vertices adjacent to every member of the current clique can ever extend it.

Branching Strategy

For each candidate vertex v:
• Branch 1 (include v): add v to clique, recurse with N(v) ∩ remaining candidates
• Branch 2 (exclude v): skip v, move to next candidate
Pruning collapses entire Branch 2 subtrees the moment |clique|+|cands| < k.

Approximation Quality & Trade-offs

This is an exact algorithm — it finds the true k-clique if one exists, or proves none exists. The trade-off is time: worst case is still exponential. In practice, heavy pruning on sparse graphs makes it far faster than brute force. On dense graphs with many cliques, pruning fires less often. The algorithm is exact but not polynomial — because Clique is NP-complete, no polynomial exact algorithm is known (unless P=NP).
Worked Example — Trace Through Backtracking ▸

Graph: {0,1,2,3}, Edges: {0-1, 1-2, 2-0, 0-3}. Find k=3 clique.

Step-by-step trace

Start: clique=[], candidates=[0,1,2,3]
→ Add 0: clique=[0], cands=[1,2,3]∩N(0)=[1,2,3]
→ → Add 1: clique=[0,1], cands=[2,3]∩N(1)=[2]
→ → → Add 2: clique=[0,1,2], |clique|=3=k → FOUND ✓

Without vertex 3 (not adjacent to 1 or 2), it never enters the candidates after we pick 1. The candidate shrinking naturally excludes it — no explicit check needed.

Prune Example

If we tried: clique=[3], candidates=[ ] (only N(3)={0}, but 0 already excluded)
→ |clique|=1 + |cands|=0 = 1 < k=3 → PRUNE. Entire subtree cut.
Complexity Analysis & Trade-offs ▸

Brute Force

Time: O(C(n,k) · k²) — enumerate all k-subsets, verify each pair.
For n=15, k=5: C(15,5)=3003 subsets × 10 pair checks = 30,030 operations.
For n=20, k=8: C(20,8)=125,970 subsets × 28 checks = ~3.5M operations.

Backtracking

Worst case: still exponential (NP-complete means no known poly-time algorithm).
In practice: pruning eliminates huge portions of the search tree.
Watch the Prune Events counter — each prune removes an entire subtree.

The P vs NP question asks whether every NP problem has a polynomial-time algorithm. If P=NP, then Clique would be solvable in O(nᶜ) time. This remains the most famous open problem in computer science.

Practical Implications

For large graphs, exact algorithms are too slow. Practitioners use:
• Greedy heuristics (find large but not necessarily maximum cliques)
• Approximation algorithms (guarantee a clique of size ≥ OPT/f(n))
• Branch-and-bound with tight bounds (state of the art for exact solutions)
